下面是我建议你们下一轮直接执行的实验计划。核心原则：

> **不再围绕 pure-soft 全程接管继续调参，而是验证“COT/LEAD 主路径 + 局部路由修复”是否能带来稳定 fixed > damaged。**

---

# 推荐实验计划

## 总目标

验证你们的 unified routing framework 是否可以从：

```text
修复 pure-soft 的退化
```

升级为：

```text
增强 COT / LEAD 主路径
```

因为目前证据很清楚：pure-soft 在 VStar 和 RealWorldQA 上都会引入长输出、重复、答案边界不稳定等退化；bestcombo 能把 pure-soft 救回来，但在 RealWorldQA fixed 上仍没有超过 COT。

所以下一阶段目标不是继续救 pure-soft，而是：

```text
以 COT / LEAD 为默认路径；
只在局部风险状态启用 route action；
观察是否能修复 COT/LEAD 错题，同时尽量不 damage 原本正确样本。
```

# Phase 2：COT 主路径 + 局部 rescue

这是第一条主实验线。

## 设计动机

RealWorldQA fixed 上：

```text
COT       66.0%
pure-soft 56.0%
bestcombo 64.0%
```

说明 pure-soft 主路径不如 COT，但 bestcombo 能显著压制 pure-soft 的长输出和截断。

因此应该测试：

> COT 本身保持 hard discrete，只在局部异常区域触发 rescue。

## 实验配置

### COT-baseline

```text
默认 COT
```

### COT + answer-zone guard

用于防答案区格式漂移：

```text
进入 answer / </think> 附近后加强答案区稳定输出
```

### COT + repeat-degen rescue

触发条件：

```text
step >= 64
AND repeat degeneration
AND output length 已经偏长
```

动作：

```text
短窗口 hard stabilization / stop-oriented answer transition
```

这里注意：COT 本来就是 hard，所以这个 route 不是“soft→hard”，而是做结构性约束，比如强制答案区、限制继续发散、或触发 answer-zone template。

### COT + local soft exploration

只在非常小的局部窗口启用 soft：

```text
relation_spike 或 diffuse_low_conf
AND 非 format token
AND 非 answer zone
AND 无 repeat degeneration
```

动作：

```text
1-2 step soft_emb
```

目的：测试 soft 是否能在 COT 错题中提供局部探索，而不是全程接管。

## 最小矩阵

```text
COT
COT + answer-zone guard
COT + repeat rescue
COT + local soft exploration
COT + repeat rescue + local soft exploration
```

## 成功标准

不要只看 accuracy。核心看：

```text
against COT:
fixed > damaged
平均长度不明显增加
maxed 不增加
failed extraction 不增加
```

如果 `local soft exploration` 让长度变长或 damage 多，说明 soft 不适合放到 COT 主路径；保留 rescue，不保留 soft。

# Phase 3：LEAD 主路径 + format/collapse guard

这是第二条主实验线，优先级和 Phase 2 一样高。

## 设计动机

LEAD 在 MMVP 和 VisuLogic 上比 bestcombo 更稳，说明它的视觉 anchor 仍然有价值；关闭 LEAD simple anchor 后，VisuLogic 从 24.67% 掉到 21.67%，说明轻量视觉先验确实有效。

但你们的 bestcombo 在 VStar 上超过 LEAD，核心来自 format boundary stabilization。

所以最有希望的是：

```text
LEAD 的视觉能力
+
你们的 format/collapse 稳定能力
```

## 实验配置

```text
LEAD
LEAD + format_cooldown2 guard
LEAD + late64_repeat_gate
LEAD + format_cooldown2 + late64_repeat_gate
LEAD + format_cooldown2 + late64_repeat_gate + answer_zone
```

## 关键观察

看两个问题：

```text
VStar 上是否超过 bestcombo / LEAD？
MMVP 和 VisuLogic 上是否保留 LEAD 优势？
RealWorldQA 上是否不伤 COT/LEAD 主路径？
```

如果这条线成立，你们的方法就从“修 pure-soft”升级为“增强已有强基线”。

# Phase 4：视觉必要子集实验

这条线不要全量跑，先做子集。

## 子集构造

对每个数据集取：

```text
S_visual = COT wrong ∩ bestcombo wrong ∩ LEAD correct
```

或者：

```text
S_lead_fix = COT wrong ∩ LEAD correct
```

这些样本更可能真的需要视觉先验，而不是格式稳定。

报告中也已经建议视觉 route 应该优先在这类子集上测试，而不是全量粗暴注入。

## 实验配置

```text
no visual bias
full image_pad λ=0.03
early-only image_pad λ=0.03
mid-only image_pad λ=0.03
phase-adaptive image_pad
LEAD simple anchor
```

## 成功标准

```text
在 S_visual 上 fixed 明显多于 damaged
在非 S_visual 上不明显伤害
```

如果 visual bias 只在这个子集有效，可以设计：

```text
visual route only when sample resembles LEAD-fix profile
```

如果仍然不稳定，就不要把 image_pad bias 放进主方法，只作为分析结果。

# Phase 5：failure-type attribution

这是为了把论文故事打牢。

## 自动标注 failure type

先做五类自动规则：

```text
missing_answer
long_output
maxed_1024
repeat_degen
answer_boundary_drift
```

再人工抽样标两类：

```text
visual_confusion
relation_error
```

## 输出矩阵

| route              | 主要修复 failure                                | 证据                            |
| ------------------ | ------------------------------------------- | ----------------------------- |
| format_cooldown    | missing_answer / format_drift / long_output | failed、maxed、length 下降        |
| late64_repeat_gate | repeat_degen / maxed                        | repeat 和截断下降                  |
| visual_bias        | visual_confusion                            | 只在 visual-needed subset fixed |
| answer_zone        | answer format                               | extraction failure 下降         |

这一步非常重要。因为你们当前最稳结论是：format cooldown 是 pure-soft 的核心稳定器，且简单削弱 format 不可行。

# Phase 6：可微形式只做 sanity check，不作为主线

现在不建议马上做 learnable differentiable router。

原因：

1. hard discrete 是目前最强收益来源，mixed format embedding 已经证明不如 hard discrete。
2. router_midbias003 在 VStar 只小幅提升，在 RealWorldQA fixed 上没有收益。 
3. 跨数据集视觉行为冲突：VStar 怕 early visual，MMVP 喜欢 early visual，VisuLogic 更偏 mid。

## 可做的小实验

只做一个低成本 sanity check：

```text
hard bestcombo
soft-gate k=100
soft-gate k=50
soft-gate k=20
```

其中：

[
\eta_t = \sigma(k(r_t-\theta))
]

只在 VStar 跑。

目标不是提分，而是验证：

```text
平滑化会不会破坏 hard boundary 收益？
```

如果 (k=100) 接近 hard rule，(k=20) 掉分，就可以反过来支持你们的核心结论：

> format boundary 需要 sharp hard routing，过度平滑会削弱结构稳定性。
